## Positioning and evidence boundary

AegisGraph is an evidence-grounded security investigation platform for a simulated fintech environment. It is a synthetic, local engineering demonstration, not a production SOC deployment, autonomous SOC, enterprise SIEM, or real banking integration. Its strongest distinction is the separation between deterministic evidence scope, replaceable providers, independently validated typed findings, and explicit analyst decisions.

The review read `README.md`, `docs/PORTFOLIO_SUMMARY.md`, `docs/DEMO.md`, `docs/INTERVIEW_NOTES.md`, `docs/VALIDATION.md`, `docs/UX_AUDIT.md`, `docs/threat-model/THREAT_MODEL.md`, all nine documents under `docs/adr/`, and the evaluation methodology and live result records. Source spot checks covered normalization, canonical types, synthetic generation, correlation, application retrieval, provider projection, and output validation.

## Engineering decisions surfaced

The case study summarizes PostgreSQL before an unneeded search service (ADR-001), separate detection and deterministic correlation (ADR-002/007), relational entity relationships (ADR-006), and narrowly typed findings with independently checked support (ADR-003/004). Untrusted telemetry projection, separate annotations, and explicit report review are explained where they affect the investigation workflow (ADR-005/008/009). The public page does not duplicate the complete ADR collection.

## Validation provenance and limits

The source commit timestamp is September 16, 2026 at 22:59:56 EDT, equivalent to September 17 UTC. The source validation records use September 17 UTC and the synthetic dataset uses September 15 UTC. Dataset time is not a live-feed timestamp.

The live record contains three named scenarios that eventually passed across six external harness requests: three HTTP 200 responses and three earlier HTTP 429 failures. The underlying cause of the 429 responses was not established.
